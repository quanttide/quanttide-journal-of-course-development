# 氛围编程课程日志

## 2026-08-26：课时3 合并版本发布（GitHub 开源协作全流程）

### 背景与问题

- 生产实习课程有 `lesson2-release`（版本发布教学），但我们的仓库采用**外部贡献模式**（外部学员 fork + PR），而 release 操作（push tag、`gh release create`）需要仓库维护权限。
- 矛盾：课程教的是学员没有权限执行的操作，任务跑不通。
- 同时 vibe-coding 课程新建了 `lesson3-github`（提交第一个 GitHub Issue），两课时在 Git/GitHub 操作上有重叠。

### 决策过程

1. 先明确了核心洞察：**不是权限问题，是仓库归属问题**——学员 fork 出来的仓库是自己的，拥有完整权限，5 个发布场景全部能在 fork 上演练。
2. 采纳"权限分层即教学内容"的思路：贡献者做有权限的事（提 Issue、改文档、PR、在 fork 演练发布），维护者做有权限的事（审核合并、上游正式发布）。
3. 用户决定：不单独保留 `lesson2-release`，把发布流程合并进 `lesson3-github`，形成单一课时完整闭环。

### 落地行为

- 创建 `vibe-coding/lesson3-github/`（index.md 场景表 + index.json 播放器数据），初始 3 场景（认识仓库 → 提 Issue → 落地修改）。
- 合并发布流程后扩展为 5 场景（约 44 分钟）：
  1. fork 仓库与权限认知（含 GitHub 权限分级讲解）
  2. 提交一个新的 Issue（四段式：位置—问题—建议—例子）
  3. 参与讨论并落地修改（PR + `Fixes #编号`）
  4. 在 fork 中演练版本发布（版本号 → CHANGELOG → tag → fork 内 Release，可反复试错）
  5. 上游正式发布与闭环（维护者 merge + tag + Release，学员见证）
- 删除 `production-internship/lesson2-release/`（10 个文件），发布异常处理（SemVer 格式错误、CHANGELOG 缺失、tag 冲突）随迁入课时 3。
- 提交：子模块 `quanttide-profile-of-course-development` 3 次（cc06015 → 2eab4e6 → 72e624a），主仓库同步更新引用。

### 价值判断

- 解决了"无权限任务跑不通"的结构性问题，把障碍变成知识点。
- 安全试错：打错 tag、删错 release 这类教学事故现在发生在 fork 里，零成本。
- 真实闭环：从 Issue 到 PR 到 Release 全程可见，学员的贡献被真实发布。
- 开放式 Issue 任务长期有效，不因单条讨论串完结而过期。
- 消除两课程重复维护成本。

### 遗留问题 / 边界

- 44 分钟可能内容过载，"文档贡献 + 版本发布"是两块独立技能。
- 在文档仓库（bylaw）上演练发布产出感弱——`docs/v0.2.0` 的 Release 没有真实发布节奏支撑，场景 4 有"为练而练"的风险。
- 场景 5 成败依赖维护者配合节奏，闭环时间不可控。
- 待办：考虑为发布演练配一个有真实迭代节奏的代码练习仓库；维护者（老师）可预先设定固定发布节奏（如每周合并发布一次）。
